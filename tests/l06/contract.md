# L06 구현 전 정답 고정

기준 90d8d8d97e4e2a0e77ddb30cf112ead4025cd70f. 사용자 승인으로 파일 15 MiB, 전체 본문 64 MiB, 파일 4개다. 그 외 정답은 지시서 4~5절 그대로다. repro.expected는 구현 뒤 변경하지 않는다.

- URL 인코딩 본문은 맵, 한글·공백·리터럴 +·빈 값 정확. 중복 키·잘못된 %·NUL·UTF-8 오류 400.
- multipart 정상 200; 파일 목록은 전송 순서. A NUL B는 3바이트, SHA-256 76fe3925c7167317f2df68454339f5ec3650e4062178b4f2be219b105a507907. 독립 원본과 전 바이트 비교.
- 파일 15 MiB 및 본문 64 MiB까지 허용, 초과 413. 파일 4개 허용, 5개 413. 지시서 나머지 필드/헤더/파트 상한도 포함한다.
- boundary 1/70 허용, 0/71·누락·중복·CRLF·끝 공백 및 닫는 경계 누락 400.
- 잘못된/중복 Content-Length 및 TE+CL 400, 길이 없는 폼 411, TE 단독 501, 지원 외 인코딩 415. 초과 헤더 431.
- 위험 파일명 400. % 인코딩 파일명은 디코딩 없이 표시용 유지. 임시 파일은 랜덤 16자리 hex이고 경로 이탈 없음.
- 중단은 handler 0·잔여 0, 응답 가능 시 400. 시간 초과 408. 모든 오류 후 다음 요청 정상.
- 저장 설정 없음/잘못됨 503. 파일 I/O/정리 실패 500, 잔여가 있다면 원문 보고. 정상/403/예외 뒤 요청 임시 파일 0, 영구 복사본 보존.
