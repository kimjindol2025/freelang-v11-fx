# B17 런타임·예약 실행·PRD 작업 기록

B17=보류. API 검수 조정 실행이 세 차례 비정상 종료해 사용자 멈춤 규칙을 적용했다. 추가 수정·시험을 중단하고 현재 구현을 WIP로 보존한다. 목록 오염 시험·맵 개선 측정·예약 언어 단위 시험·정식 고정점은 확인했지만 서버 예약 인수·브라우저·전체 회귀는 완료하지 못했다. 기존 결과를 이번 회차 통과로 대체하지 않는다.

## 출발점과 종료 조건

- FX 출발: 7f6e830456533226b3d6d67aabbf3f063ee78384
- blog1 출발: dcc9e1a6a955874bc7cc0c4258caf085f3d4f89b
- 두 출발 작업 트리 CLEAN 확인 후 각각 fix/b17-timer-prd 가지를 분리했다.
- 일반 임시 자료는 작업 전용 저장 영역 <가림>에만 두고 TMPDIR를 전달했다. 무거운 실행은 ps 확인, 공용 flock, 2147483648바이트 cgroup·swap0·core0 아래 순차 실행했다. 잠금을 강제로 풀지 않았다.
- 원래 시험·정답·러너·시간 제한·PRD 원표·seed는 변경하지 않았다. 새 B17 시험과 별도 검수 조정 스크립트를 추가했으며, 아래 오류는 이 새 준비 부분에서 발생했다.

## 런타임 두 곳의 확인

목록 공간 공유가 들어온 실제 커밋은 B13의 1c0ee27ac015e4e5f4414e958a392798822defe4, 커밋 날짜는2026-11-13이다. B15 또는 B16에서 처음 들어온 변경이 아니었다. 맵의 순차 키 비교는 B15의 1dd15864807fd438ef77e058dba7ae2841ec51bf에서 들어왔다.

B16 파일 목록은 B15 출발점 대비 해당 회차 작업분이며, 누적 비교에 보이는 collection/map 변경은 앞선 B13/B15 커밋이므로 목록과 다르게 보인다. B16의 FX 문서·blog1 스타일 변경 외에 새 런타임 변경이 숨겨져 있던 것은 아니다.

목록 시험은 a를 b에 복사한 뒤 b 추가, 원래 a에서 다른 가지 추가, b의 항목 변경을 확인했다. 원본 길이와 내용, 앞서 만든 가지 모두 유지됐다. 네 조건 통과·값 섞임0이었다. 기존 구현은 새 불변 헤더/논리 길이와 append-only 저장소를 분리하고, 사용된 접미 영역에 원자적 예약을 한다. 이번에는 collection.c를 수정하지 않았다. 이것을 모든 동시 실행 형태에 대한 증명으로 확대하지 않는다.

고정한 새 시험 tests/b17-runtime-safety.c를 a5e234d2467a1261620c23b86f26d936d176e7de로 먼저 커밋했다. 정규화·중복 키의 마지막 값·첫 위치·NUL 포함 키·빈 키·Unicode도 별도 큰 맵 경로에서 확인했다. 이 시험들의 기존 기대값을 수정하지 않았다.

## 예약 언어 기능과 제품 연결

새 native builtin schedule_at(epoch_ms, callback)은 기존 협력형 타이머 큐와 관리형 promise를 재사용한다. 인자는 유한한 정수 밀리초와 함수 두 개이며, 잘못된 인자는 명시적 오류다. 과거 시각은 비동기로 실행하고 미래 시각은 wall clock을 다시 확인해 이르지 않게 실행한다. 결과·콜백 오류·취소가 관측되며, 소유 스레드 정리 뒤 콜백은 호출되지 않는다. cron이나 새 상주 스레드를 만들지 않았다.

정해진 시각 이전 실행 금지·즉시 반환·pending·과거 시각·순서/한 번 실행·결과·예외·잘못된 인자11개가 통과했다. 별도 취소 시험 원문은 AT_CANCEL_CALLBACKS=0, AT_CANCEL_ERROR=timer cancelled였다. 첫 실행에는 제가 이전 process.o를 연결하는 빌드 준비 오류가 있었고, 타이머 헤더를 포함하는 실제 파일 runtime/process.c를 확인한 뒤 모든 런타임 객체를 새로 빌드했다. 같은 새 단위 정답을 유지해 통과했다.

format_date_utc는 기존 서식을 UTC로 출력한다. 명시적 오프셋·UTC·한국 시간·윤일·날짜 경계·음수 밀리초·중복 시각의 두 오프셋9개를 UTC/Asia/Seoul/America/New_York의 별도 프로세스에서 통과했다. 기존 현지 시각 API의 New York 중복 시각은 앞선 시각, 누락 시각은 앞으로 보정되는 두 조건도 확인했다. 기존 date_parse/format_date의 의미는 변경하지 않았다. 범용 IANA 이름 검증을 새로 완료했다고 보고하지 않는다.

블로그 코드 초안은 기존 HTTP 이벤트 루프에서 예약을 등록하고 매 주기 저장된 pending 예약을 확인한다. 재시작 때 저장 자료에서 놓친 예약을 처리하도록 연결했다. 기존 승인/자동 발행 설정을 존중하며, 실행 오류·최근 시각·실패 횟수는 감독 화면에 드러나게 했다. 그러나 실제 서버에서 방문0건·예정+5초·재시작2회·중복0을 확인하는 인수 시험은 미실행이다. 언어 단위 통과를 제품 예약 통과로 바꾸지 않는다.

## 정책 없는 제품 코드 초안과 실제 확인 범위

- P01: 검색, 상태/분류 필터, 페이지 이동, 선택 후 대상 확인, 일괄 작업 성공/실패 표시를 구현했다. 검색·필터·페이지 이동은 실제 응답으로 확인했지만 일괄 작업 인수는 아직 실행되지 않았다.
- P02: 예약 화면의 제목/주소/시각 확인, UTC/한국 시간 입력과 UTC 저장, 잘못된 날짜·과거 시각 거부, 저장 실패를 성공 redirect로 바꾸지 않는 처리를 추가했다. 예약 입력·발행·수정·실패 안내·발행 취소 응답은 확인했지만 익명 공개 경로·마지막 독립 reader·저장 실패 주입 등 전체 인수는 미완료다.
- S01: 기존 편집 화면을 페이지에 재사용하고 분류 메뉴를 추가했다. 페이지에서 새 자동저장 정책은 활성화하지 않았다. 컴파일만 확인했고 브라우저·메뉴 순서·공개/비공개 전체 흐름은 미실행이다.

시험 HTML/서버/자료 준비는 tests 아래에 두고 export-ignore로 생산 묶음에서 제외하도록 작성했다. 새 JS 파일은 없으며 기존 제품 편집기 JS는 변경하지 않았다. 새 HTML의 브라우저 전용 시험 스크립트는 실제 합성 로그인에 사용할 예정이지만 이번에는 실행하지 못했다. 실제 계정·운영 DB·배포는 사용하지 않았다.
