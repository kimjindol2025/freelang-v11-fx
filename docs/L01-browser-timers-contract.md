# L01: 자동저장 선행 브라우저 타이머 계약

상태: 구현 전 `.fl` 시험·정답 고정. 실행 결과는 아직 없다. 블로그 자동저장 완료 판정과 별개다.

## 근거와 범위

기준 커밋 `25b3e2a6840805003cf58116a7879c15c57c860a`의 `runtime/browser-target.h` 공개 builtin 표에는 브라우저 타이머가 없다. `self/browser-core.fl`의 언어 지원 로직과 compiler 전용 primitive 방식을 따른다. native 타이머가 있다는 이유로 browser 지원을 인정하지 않는다.

새 공개 API는 두 개만 추가한다.

| API | 계약 |
|---|---|
| `(browser-after! milliseconds callback)` | 정확히 두 인자. 지연은 정수 `0..2147483647`, callback은 함수. 불투명 handle 반환. 0도 현재 동기 작업이 끝난 뒤 실행. 한 번만 호출하고 인자는 전달하지 않는다. |
| `(browser-cancel! handle)` | 정확히 한 인자. 이 API가 만든 handle만 허용. pending이면 취소 후 true, 이미 취소했거나 실행을 시작했으면 false. 위조 값은 오류. |

범위·타입·인자 수 위반은 동기 오류이며 타이머를 만들거나 다른 handle을 변경하지 않는다. callback을 호출하기 전에 fired 상태로 전환한다. callback 예외는 일반 브라우저 예외로 전달하며 자동 재실행하지 않는다. 취소·실행 후 callback 참조를 해제한다. handle의 소유 정보는 private WeakMap에 두고 서로 다른 handle은 값이 같아 보이더라도 동일하지 않다. 공개 상태 조회·반복 타이머는 이번 범위가 아니다.

브라우저 스케줄러는 탭 상태/부하로 지연될 수 있다. 정확한 벽시계 시간 보장은 하지 않는다. 블로그의 30초 목표는 실제 제품 시험에서 따로 확인한다.

## 구현 경계

- 상태·검증·한 번 호출·참조 해제는 `.fl`로 작성한다.
- C 출력기는 고정 표준 timer 호출·취소 primitive만 연결한다. 사람이 쓴 앱 JS나 JS 알고리즘 문자열을 넣지 않는다.
- 생성 JS는 수정하지 않고 두 번 생성해 동일한지 확인한다.
- native API, 운영 자료, 다른 제품 체크포인트는 바꾸지 않는다.

## 고정 자체 시험

`tests/l01/browser-timers.fl`과 같은 이름의 `.expected`가 20개 정답을 고정한다. 비동기 0 지연·한 번 실행·실행 중 취소·서로 독립인 handle·취소 중복·취소된 callback 미실행·중첩 예약·지연 예약·상한·위조 handle·잘못된 지연/함수/인자 수를 확인한다. proof는 마지막 timer에서 한 번에 출력해 일부 통과를 완료로 읽지 않게 한다. 20ms·200ms는 시험 순서용이며 실시간 성능 수치가 아니다.

추가 인수: 실제 Chrome에서 callback 예외가 한 번 관찰되고 같은 callback이 재실행되지 않는지 별도 fixture/수동 주입 없는 C CDP 관측으로 확인해야 한다. 위 20개 시험만으로 예외 인수까지 완료 처리하지 않는다.

## 순서와 중단 규칙

1. 이 계약·`.fl`·정답을 먼저 커밋한다.
2. 수정 전 생성 실패의 원문·종료 코드·소스 SHA를 기록한다.

4. 실제 loopback HTTP + Chrome에서 정답 20개와 예외 관측을 확인한다. compiler generation만으로 완료 판정하지 않는다.
5. 의미/이벤트/DOM/블록 모델 회귀, 생성 재현성·private API 거부, native 회귀와 bootstrap을 확인한다. strace의 금지 실행 감사는 기존 내부 tracer와 중첩하지 않는다.
6. Forgejo 다음 GitHub로 같은 작업 가지를 푸시하고 두 HEAD를 직접 확인한다.
