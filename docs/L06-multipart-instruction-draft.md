# L06 파일 업로드(multipart) 구현 지시서 초안

상태: **문서만 작성, 구현·시험 실행 전** · 작성일: 2026-10-28

## 1. 목적과 시작 조건

L07의 바이너리 파일 계약 위에 네이티브 FreeLang HTTP 폼·업로드를 만든다. multipart 여러 파일을 손실 없이 받고, 잘못되거나 중단된 요청의 임시 파일을 정리한다. 블로그를 불러오지 않는 `.fl` HTTP 서버와 실제 소켓 요청으로 언어 기능을 판정한다.

기준은 `freelang-v11-fx`의 `feat/l07-binary-io`, 전체 HEAD `8379fd76adc6c2934c9d056d72b4f94b9f4226d0`이다. 이 문서는 그 커밋에서 만든 **새 가지 `docs/l06-multipart-plan`** 에 작성한다. 별도 구현 승인 뒤 구현용 새 가지에서 시작하며, 이미 추가된 관련 수정이 있다면 차이를 먼저 조사한다. 이 문서는 구현 승인이 아니다.

**호환 문제 판단: URL 인코딩 폼 본문을 맵으로 받는 문제도 L06에 포함한다.** 두 형식 모두 HTTP 본문 수신·Content-Type 분기·필드 맵 생성의 문제다. 이를 미루면 L08에서 로그인·글 저장 폼을 이전할 때 막힌다. 날짜·`get` 기본값·브라우저 실행 문제까지 확대하지 않는다.

## 3. 허용 범위와 금지

허용: `.fl`, fx C 런타임·생성 C, Markdown, 독립 바이너리 fixture, 필요한 Bash 시험 구동과 작은 C 소켓/장애 재현 도구. 기존 네이티브 compiler로 생성한 ELF만 FreeLang 실행기로 사용한다. **새 TS·수작업 JS·Python, Node 실행, Python을 쓰는 `fl-build.sh`는 금지**한다.

변경 영향은 HTTP/TLS 수신자, 요청 맵 생성자, 공개 getter·컴파일러 연결, 요청 종료/예외 처리, 로그, 파일 임시 저장, 시험·fixture까지 조사한다. 기존 JSON·일반 본문·라우팅·정적 응답을 회귀 확인한다. 쿼리 API 전체 재작성, 이미지 변환·형식 판별, 인증·CSRF 정책 변경, 영구 저장 거래, 브라우저 편집기는 범위 밖이다. 블로그의 단일 이미지 제한을 언어의 복수 파일 지원에 맞춘다는 이유로 풀지 않는다.

서버 23·25 접속·작업, 운영 WAL·이미지·백업 원본 변경/삭제, 다른 서비스 중지, sudo·시스템 설정 변경, 합치기·배포·강제 푸시는 금지한다. 시험은 격리된 복사본·임시 루트와 자신이 시작한 서버만 사용한다. 빈 포트는 서버의 포트 0 바인딩 등으로 원자적으로 선택하고 실제 배정 포트를 전달한다. 포트 충돌 때문에 남의 프로세스를 끄지 않는다. 보고에는 비밀 값·비밀 게시 주소·로컬 절대 경로를 적지 않는다.

## 4. API·오류 계약 초안

### 4.1 요청 맵과 URL 인코딩 호환

| 공개 호출·키 | 성공 시 계약 |
|---|---|
| `(get req "body")`, `(server_req_body req)` | URL 인코딩 폼과 multipart는 텍스트 필드 맵. JSON의 기존 맵/벡터 처리는 유지. 다른 본문의 기존 반환형을 조용히 변경하지 않음 |
| `(server_req_fields req)` | 두 폼 형식의 텍스트 필드 맵. 폼이 아니면 빈 맵 |
| `(server_req_files req)` | multipart 파일 메타데이터의 전송 순서 벡터. 그 밖에는 빈 벡터 |
| 파일 맵 | `fieldname`, `originalname`, `mimetype`, `size`, `filename`, `path`. 앞의 두 이름·MIME은 검증 전 사용자 입력이며, `filename`은 런타임 생성 이름, `path`는 L07에 전달 가능한 임시 경로 |

동일 이름의 파일 파트도 각각 벡터에 보존한다. `size`는 실제 저장한 파일 바이트 수다. MIME 생략 시 `application/octet-stream`을 사용하며 확장자·MIME을 안전한 이미지의 증거로 삼지 않는다. 파일 내용은 필드 맵으로 복사하지 않는다.

Content-Type은 대소문자·매개변수를 파싱해 정확한 media type으로 분기한다. URL 인코딩은 `&`·첫 `=`로 분리한 뒤 `%HH`를 정확히 한 번 해석하고 `+`를 공백으로 바꾼다. `a=`·`a`는 빈 값, 빈 본문은 빈 맵, 빈 이름·잘못된 `%`·NUL·잘못된 UTF-8은 400이다. UTF-8 한글·인코딩된 `&`·`=`·`+`를 보존한다. 고정 1024바이트 쿼리 버퍼로 본문을 자르지 않는다.

이 초안의 폼 정책은 **중복 텍스트 이름 및 텍스트/파일 이름 충돌을 400으로 거부**한다. 같은 이름의 여러 파일은 허용한다. 이는 인증 필드의 모호함을 막기 위한 지원 제한이며, 반복 텍스트 필드를 일반적으로 보존하는 API는 제공하지 않는다. 쿼리의 기존 중복 키 정책까지 변경하지 않는다. 기존 폼 호출자가 반복 텍스트를 요구하는지는 구현 전 전수 조사하고, 발견되면 계약 변경을 사용자 결정으로 남긴다.

### 4.2 multipart와 바이너리

1. `multipart/form-data`의 boundary는 필수이며 중복 매개변수는 거부한다. 따옴표 있는 값도 해석하고 RFC 2046 문법의 ASCII 1~70바이트·마지막 공백 금지를 확인한다. 빈 값·71바이트·CR/LF 주입은 400이다.
2. 각 파트는 유효한 `Content-Disposition: form-data; name=...`를 가져야 한다. 파일은 `filename` 유무로 구분한다. 중복 disposition/name/filename 매개변수, 접힌 헤더·잘린 헤더·잘못된 인용은 거부한다. 중첩 multipart와 비UTF-8 텍스트 charset, Content-Transfer-Encoding은 415, `filename*`는 400으로 제한한다. 기타 알 수 없는 파트 헤더는 값으로 실행하지 않고 무시하되 헤더 상한에 센다.
3. 경계는 파트 시작/CRLF와 올바른 구분자 끝에서만 인식한다. TCP 수신 조각을 가로질러도 동일해야 한다. 닮은 접두사·파일 내부 NUL·0~255·비UTF-8은 원문을 보존한다. 실제 구분자와 충돌하는 파일 내용은 클라이언트가 다른 boundary로 보내야 하며 무조건 복구한다고 약속하지 않는다. 구분자 앞 CRLF는 파일에 더하지 않으며 원래 파일의 CRLF는 보존한다. preamble/epilogue는 총량 상한 안에서 무시한다.
4. 파일은 L07 `file-write-result`·`file-append-result`로 실제 길이의 바이트를 기록하고 결과 `ok`·`bytes`·flush/close 실패를 확인한다. `.fl` 검증은 `file-read-result`, 영구 복사 예시는 `file-copy-result`를 쓴다. `strlen`·문자열 표시·재인코딩으로 바이트 수를 계산하지 않는다. L07의 64 MiB는 업로드 허용량이 아니다.
5. 이름 있는 0바이트 파일은 정상 파일이다. `filename=""`·빈 내용은 미선택 파일로 건너뛰되 파트 수에는 센다. 빈 파일명에 내용이 있으면 400이다. 마지막 닫는 경계와 모든 파일의 저장 완료 전에는 handler에 fields/files를 공개하지 않는다.

### 4.3 상한과 HTTP 수신

아래 수치는 **구현 전 고정할 제안 계약**이며 현재 구현됐다는 뜻이 아니다. 크기는 바이트, MiB는 1024×1024, KiB는 1024다.

| 대상 | 제안 상한·처리 |
|---|---|
| 전체 HTTP 본문 | 10 MiB, multipart 헤더·구분자·무시하는 영역 포함. 초과 413 |
| 파일 하나 / 파일 수 | 5 MiB / 4개. 초과 413 |
| 텍스트 필드 하나 / 합계 / 개수 | 64 KiB / 256 KiB / 32개. 초과 413 |
| 전체 파트 수 | 건너뛴 파트까지 36개. 초과 413 |
| 파트 헤더 합계 / 개수 | 빈 줄까지 8 KiB / 16개. 초과 413 |
| 필드 이름 / 원본 파일명 | UTF-8 128 / 255바이트. 초과 413 |
| HTTP 헤더 | 기존 32768바이트를 헤더에만 적용. 초과 431 |
| 업로드 시간 | 본문 수신 시작부터 절대 60초. 조금씩 보내도 갱신하지 않음. 초과 408 |

파일당 상한과 전체 상한을 함께 적용한다. 예를 들어 5 MiB 파일 두 개는 부가 바이트까지 합치면 전체 상한을 넘는다. 전체 본문을 스택의 큰 배열로 대체하지 말고 상한 있는 버퍼/파일 저장으로 처리하며 할당 실패도 전파한다.

Content-Length는 **헤더 구간에서만** 십진 정수·오버플로·중복을 검사한다. 음수·문법 오류·중복은 400, 유효한 수의 전체 상한 초과는 413이다. 이 단계의 폼은 명시적 길이를 요구하며 누락 시 411이다. Transfer-Encoding과 Content-Length 동시 지정은 400, Transfer-Encoding 단독은 미지원 501로 연결을 닫는다. chunked 구현 완료나 완전한 HTTP/1.1 호환으로 보고하지 않는다. Content-Encoding 압축은 415로 거부한다.

수신 완료 조건은 실제 받은 바이트 수와 선언 길이의 일치다. EOF·timeout·버퍼 끝을 정상 완료로 처리하지 않는다. L06 폼 응답은 `Connection: close`로 닫고 남은 수신 바이트를 다음 요청으로 실행하지 않는다. 다른 Content-Type의 기존 연결 동작은 회귀 확인한다. TLS도 동일한 본문 검증을 거치게 하며 별도 경로를 방치하지 않는다.

### 4.4 파일명·임시 파일 수명

원본 이름은 저장 경로로 연결하지 않는다. `.`, `..`, `/`, `\`, 드라이브/콜론, NUL·제어문자가 있는 원본 이름은 400이다. 파일명의 `%HH`는 URL 디코딩하지 않고 표시용 그대로 보존하므로 `%2e%2e%2f`도 디렉터리로 해석되지 않는다. 응답·화면 출력 시 HTML 안전 처리는 호출자 계약으로 남긴다.

업로드 저장은 유효한 `FL_FILE_BASE`와 `TMPDIR=설정 루트/tmp`를 요구한다. 그 아래 `fl-uploads`에 런타임이 무작위 16자리 hex 이름(확장자 없음)을 생성해 기존 블로그 검증과 연결한다. 디렉터리 0700·파일 0600, root 기준 no-follow 디렉터리 FD·독점 생성으로 충돌/심볼릭 링크를 거부한다. 충돌 시 기존 파일을 열어 자르지 않고 새 이름으로 제한 횟수 재시도한다. root 설정이 없으면 업로드 저장을 503으로 거부한다. 파일 없는 URL 인코딩 폼은 저장 설정을 요구하지 않는다.

**L07 API만으로 안전한 독점 생성·삭제가 완성됐다고 쓰지 않는다.** 최소 C 런타임의 임시 이름 예약·소유권 추적·FD 기준 삭제를 추가하고 실제 파일 바이트 I/O는 L07 checked 경로를 사용한다. 생성한 파일과 부모 디렉터리의 소유/동일성을 쓰기·정리 때 검증한다. 범용 delete에 사용자가 준 경로를 넘기지 않는다.

요청이 만든 임시 파일만 추적한다. 파싱·상한·쓰기 실패나 중단 시 전부 정리하며 handler 호출은 0회다. 정상 수신 후에는 handler가 사용하는 동안만 유지하고 반환·403·예외·응답 실패에도 정리한다. handler가 L07으로 복사한 영구 파일은 지우지 않는다. 앱이 먼저 임시 파일을 지웠다면 ENOENT는 정리 성공으로 취급한다. 정상 응답 전 정리를 마치고 실패를 숨기지 않는다. 이미 실행한 handler의 DB/영구 파일 작업까지 HTTP 런타임이 되돌린다고 약속하지 않는다.

정상 종료는 해당 서버가 소유한 요청을 정리한다. SIGKILL 직후 정리는 보장할 수 없으므로 다음 시작에서 이전 인스턴스의 소유 기록을 검증해 남은 임시 파일만 회수한다. 살아 있는 다른 worker/인스턴스·다른 파일을 일괄 삭제하지 않는다. 소유권을 증명하지 못하면 삭제를 보류하고 미확인/오류로 남긴다.

### 4.5 오류 계약

실패 응답은 고정 코드만 담은 `{"error":"코드"}` JSON과 해당 HTTP 상태로 보낸다. 일부 fields/files·원본 데이터·비밀·실제 임시 경로를 응답에 넣지 않는다. 폼 본문은 디버그 수준 2에서도 출력하지 않는다. 정상 파싱 뒤 handler의 응답 형식은 기존 API를 유지한다.

| HTTP | 코드·조건 |
|---|---|
| 400 | `BAD_CONTENT_LENGTH`, `BAD_BOUNDARY`, `BAD_MULTIPART`, `BAD_PART_HEADER`, `BAD_FIELD_ENCODING`, `DUPLICATE_FIELD`, `UNSAFE_FILENAME`, `INCOMPLETE_BODY` |
| 408 / 411 | `UPLOAD_TIMEOUT` / `LENGTH_REQUIRED` |
| 413 / 431 | `UPLOAD_LIMIT` / `HEADER_LIMIT` |
| 415 / 501 | `UNSUPPORTED_ENCODING` / `TRANSFER_ENCODING_UNSUPPORTED` |
| 503 | `UPLOAD_STORAGE_UNAVAILABLE` |
| 500 | `UPLOAD_IO_FAILED`, `UPLOAD_CLEANUP_FAILED`. L07의 상세 오류는 비밀 없는 내부 진단으로 연결 |

클라이언트가 이미 연결을 끊었으면 HTTP 오류를 받았다고 보고하지 않는다. 연결 중단 원인·handler 0회·임시 파일 0개를 증거로 남긴다. 정리 자체가 실패했다면 0개라고 쓰지 않고 잔여 개수와 제한된 재정리 결과를 보고한다. 잘못된 요청으로 프로세스를 종료하거나 다음 요청을 오염시키지 않는다.

## 5. FreeLang 자체 시험과 합격 기준

시험 서버·assert는 `.fl`에서 공개 getter와 L07 API를 호출한다. 일반 요청은 curl, 조각 수신·잘못된 프레이밍·중단은 작은 C 소켓 클라이언트로 **실제 loopback HTTP**를 보낸다. C 파서 직접 호출은 보조 시험일 뿐이다. TLS는 시험용 인증서로 같은 핵심 표본을 실제 요청해 우회가 없음을 확인한다. 필요한 의존성이 없으면 미실행으로 남긴다.

독립 C/Bash fixture로 바이트와 SHA-256을 만들고 원본·기대 JSON/오류·handler 호출 수·잔여 파일 수를 구현 전 커밋한다. 기대 출력에서 무작위 이름·포트는 형식/고유성으로 검사하고 제거한 나머지 의미 값은 고정한다. 파일 경로는 응답에 노출하지 않고 `.fl` handler 내부에서 읽어 바이트·길이·독립 해시를 대조한다. unavailable 해시 stub은 정답 근거가 아니다.

| 시험 | 고정할 기대 결과·증거 |
|---|---|
| 수정 전 최소 재현 | 기존 API만 쓰는 `.fl` handler에 실제 URL 인코딩 폼을 보내 본문 맵 기대값의 실패를 보존. 새 getter 미정의 컴파일 오류만으로 HTTP 실패 재현을 대체하지 않음 |
| 폼 맵 | `name=%ED%95%9C%EA%B8%80&space=a+b&plus=%2B&eq=%3D&empty=` → 한글, `a b`, `+`, `=`, 빈 문자열. 1024바이트 초과·빈 본문도 정확. 중복 키·잘못된 `%`·NUL·잘못된 UTF-8은 400, handler 0회 |
| 정상 multipart | 텍스트+파일, 파일 없는 폼, 같은/다른 필드 이름의 여러 파일을 200으로 시험. 메타데이터·순서·bytes·원본 불변을 검사 |
| 바이너리 무손실 | `41 00 42`는 3바이트, SHA-256 `76fe3925c7167317f2df68454339f5ec3650e4062178b4f2be219b105a507907`. 앞/뒤 NUL·0~255·비UTF-8·PNG/GIF/JPEG 표본도 바이트 비교와 독립 해시 일치 |
| 기존 수신 버퍼 초과 | 파일 65535·65536·65537바이트 및 여러 블록을 실제 HTTP로 보내 모두 정확. 10 MiB 지원은 상한 경계 시험으로 별도 증명 |
| 파일 경계 | 0바이트 이름 있는 파일 보존. 미선택 파일은 생략. 빈 이름+내용은 400. 파일 수 4/5는 다른 상한 안에서 성공/413 |
| 용량 경계 | 각 바이트 상한 n−1/n/n+1, 개수 n/n+1을 다른 상한에 가리지 않게 구성. 본문 총량은 multipart 부가 바이트 포함 계산. 허용 안에서는 정확, 초과는 413·handler 0·요청 임시 파일 0 |
| boundary 문법 | 길이 1/70·따옴표 값 정상, 0/71·누락/중복·CRLF·마지막 공백은 400. 닫는 경계 누락·잘못된 파트 헤더도 400 |
| 수신 조각·닮은 경계 | boundary/CRLF/헤더/NUL 각 위치를 TCP write 사이에서 분할해도 결과 동일. `--boundaryX` 등 비구분자 바이트는 그대로 보존 |
| 길이·프레이밍 | 음수/잘못된/중복 Content-Length·길이/TE 동시 지정 400, 길이 누락 411, TE 단독 501, 압축·중첩·지원 외 인코딩 415. handler 0·연결 종료. 뒤에 붙인 두 번째 요청을 실행하지 않음 |
| 중단·시간 초과 | 파트 헤더/파일 중간에서 half-close·완전 종료, 선언 길이 미달, 60초 초과·지속 소량 송신 시험. 응답 가능 시 400/408, 불가능 시 중단 기록. handler 0·임시 파일 0·다음 정상 연결 200 |
| 경로 이탈 | `../x`·절대 경로·역슬래시·드라이브·NUL·제어문자 400. `%2e%2e%2f`는 표시용 원문만 유지, 실제 저장명은 hex. 외부 sentinel 불변 |
| 저장소 경계 | FL_FILE_BASE 없음/잘못됨 503, 심볼릭 링크·이름 충돌·권한 오류를 거부하고 기존 파일 불변. 독점 생성 이름은 충돌 없이 분리 |
| 정리·복수 요청 | 두 번째 파일 실패 시 첫 파일도 정리. handler 정상/403/예외·전송 중단 후 0개. 동시 요청 간 삭제 없음. 앱의 선삭제는 정상, 영구 복사본은 보존 |
| 장애·재시작 | 시험 전용 fault 주입으로 짧은 쓰기·flush/close·할당·unlink 실패를 실제 HTTP 경로로 재현해 500/잔여 수를 확인. 자기 시험 서버만 강제 종료 후 재시작해 소유 임시 파일 회수·다른 인스턴스 파일 보존 |
| 로그·TLS·회귀 | 고정된 가짜 비밀 표식이 디버그 로그/오류에 없음. TLS 핵심 양성·음성 재시험. JSON·일반 본문·쿼리·기존 getter 회귀 |
| L07·네이티브 자체 시험 | 기존 기대값을 바꾸지 않고 L07 자체 시험·런타임 회귀·전체 자체 시험과 `verify-native-bootstrap.sh` 통과. Node·npm·npx·JS/TS 실행기·Python 호출 각각 0 |

장애 주입은 시험 바이너리에서만 사용한다. 운영 디스크 채우기·남의 권한/프로세스 변경은 금지한다. HTTP 상태만 맞고 파일이 잘리거나 남아 있으면 실패다. TLS·재시작·오류 중 하나라도 필수 시험이 미실행이면 전체 완료로 쓰지 않는다.

## 6. 구현·시험 순서 초안

1. 구현 승인 뒤 기준 SHA·깨끗한 새 가지·호출자·C compiler·네이티브 빌드 의존성을 확인한다. HTTP/TLS·handler 예외 경로와 L07 저장 함수의 연결부터 검토한다.
2. `.fl` 최소 재현 서버, 실제 HTTP 클라이언트, 독립 fixture, 계약·정답 파일을 **먼저 커밋**한다. 수정 전 실제 실패 출력·종료 코드·요청/응답을 보존한다. 정답을 파서 수정에 맞춰 고치지 않는다. 다른 필수 표본의 정답도 각 기능 수정 전에 고정한다.
3. 수신 길이·헤더/본문 경계·폼 맵·공개 getter를 최소 수정한 뒤 multipart·상한·안전한 임시 저장·정리·로그를 연결한다. 새 기능을 우회하는 블로그 전용 C 처리로 완료하지 않는다.
4. 같은 정답으로 표 전체의 실제 HTTP 자체 시험을 수행하고 각 요청의 상태·바이트/해시·handler 수·잔여 수·서버 생존을 기록한다. 잘못된 요청 뒤 정상 요청, 복수 파일·동시 요청·재시작까지 확인한다.
5. 전체 자체 시험·L07 회귀와 `bash scripts/verify-native-bootstrap.sh`를 실행한다. 각 실제 빌드/시험 명령을 `strace -f -e trace=execve` 아래에서 실행하고 원문·종료 코드·프로세스 집계를 제출한다. 새 L06 시험 실행 명령은 작성 후 확정하며, 지금 존재하거나 실행됐다고 쓰지 않는다.
6. 실패/미실행을 남긴 한국어 보고서와 증거를 커밋한다. Forgejo → GitHub 순서로 같은 구현 작업 가지를 정상 푸시하고 각각 원격 ref를 다시 읽어 전체 HEAD SHA를 보고한다. 합치기·배포는 하지 않는다.

이번 요청은 1~6의 실행을 승인하지 않는다. **이번에는 이 초안 Markdown만 커밋·푸시**한다.

## 7. 제출물과 완료 판정

향후 구현 제출물은 기준·정답 선행·수정·보고 커밋의 전체 SHA, `.fl` 시험·fixture·고정 정답, 실행 명령/종료 코드/통과·실패 수, 실제 HTTP 요청·응답과 독립 바이트/해시 비교, 중단·정리·재시작 로그, 네이티브 전체 시험·부트스트랩 결과, 금지 실행기 각각 0인 strace 근거다. 터미널 캡처는 원문 로그와 함께 제출하고 비밀·로컬 경로를 가린다. C 단위 시험이나 블로그 HTTP 200만으로 언어 기능 완료를 판정하지 않는다.

**확인한 것:** 위 기준 커밋의 소스·L07 계약과 블로그 호출자의 API 요구를 읽었다. L06 초안에 URL 인코딩 맵 문제를 함께 다루기로 범위를 기록했다.

**미확인:** 위 새 API·상한·저장/정리·HTTP/TLS·네이티브 시험은 제안과 향후 지시다. 이번 문서 작업에서 구현하거나 시험 실행하지 않았으며 L06 완료·L08 이전 성공을 주장하지 않는다. 실제 현재 브랜치와 양쪽 원격 HEAD 일치는 문서 커밋·푸시 후 별도 보고한다.
