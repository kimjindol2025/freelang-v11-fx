# L08 호출 목록과 바인딩 근거

[지시서 초안](https://github.com/kimjindol2025/freelang-v11-fx/blob/docs/l08-compat-plan/docs/L08-compat-instruction-draft.md)의 조사 부록이다. **정적 조사이며 실행 호환 확인이 아니다.**

## 집계 방법과 한계

Bash/awk로 추적 파일을 읽어 따옴표 문자열(escape·여러 줄 포함)과 `;` 주석을 제외했다. `(` 뒤 머리 이름을 세고 `define`·`defn`의 이름을 별도 수집했다. 조사 파일 어디엔가 같은 이름의 선언이 있는 호출은 내부 이름으로 분류했다. 이것은 진입점별 scope/import 분석을 대신하지 않는다. `map/filter/reduce/any?/every?/sort-by`의 함수 값 인자와 `swap!`의 갱신 함수도 보완 조사했으며 머리 호출에 없던 `update` 1종(값 참조 5개)을 추가했다. `load` 안 문자열 경로와 HTTP 처리 함수 이름은 별도로 소스 검토했다.

74개 파일, 머리 호출 12751곳, 머리 586종, 그중 소스 선언 집합과 같은 이름 423종, 외부 머리 163종 + 값 전달만 하는 update 1종 = **외부 점검 164종**. 이 164에는 문법 형식이 포함된다. 아래 `-`는 해당 방식의 명시적 바인딩을 찾지 못했다는 뜻이다. 다른 분기·fallback·생성 C까지 실행해 “없는 함수 오류”를 측정한 것은 아니다.

컴파일러 열은 X `self/cgc-main.fl`에서 `$op`와 정확한 이름을 비교하는 분기의 행 번호다. C 열은 `c-name` 규칙으로 얻은 이름의 정확한 `FLValue` 선언이다. 연산자·문법 이름은 C 심볼로 억지 변환하지 않았다. 이름이 다른 native primitive의 존재는 초안의 C 항목에서 함께 설명한다. 단일 분기/선언이 있다는 사실이 호환의 증거가 되지는 않는다. 기대 계약·재현 `.fl` 표·언어 수정 방향은 각 C 항목에 연결했다.

X = `7566eb1aa3c07de617e71482e0a051587d718725`, B = `013a5b339068412332ae12a7ef0c412963a3a880`, D = `88b4aa2ca11e5355240a1d93ece8321315c669cc`. 근거 링크는 고정 SHA를 사용한다.
